## 01:15 UTC — Resilience plan

Brad asked for a resilience system so the agent doesn't sit idle with work to do.

**Root cause:** No heartbeat cron job existed. HEARTBEAT.md defined the task but nothing implemented it. Only GC and budget-reset cron jobs were running.

**Solution implemented (3 layers):**

### Layer 1: Heartbeat Cron (the missing crank)
- Job: `carbon-agent-heartbeat` (id: b17e876e-b319-4700-bfd4-f2dfed993c83)
- Schedule: every 30 minutes
- Isolated agentTurn with 2h timeout
- Does: mutex check → reconcile → PR feedback → build dispatch → groom → GC
- OpenClaw orchestrates, Claude Code (`claude -p`) does the programming

### Layer 2: Resilience Rules (in CARBON_AGENT.md)
- Build mutex: process check + lockfile at `/home/openclaw/carbon/.build-lock`
- Staleness detection: agent:working >90min + no process + no PR → stale → recover
- Build timeout: 90 min hard kill on `claude -p`
- Crash recovery: automatic via staleness detection on next wake

### Layer 3: Watchdog
- Job: `carbon-agent-watchdog` (id: ae38ca3f-f990-4094-b1eb-85be430c850f)
- Schedule: every 2 hours
- Checks: heartbeat health, stuck state, disk space
- Alerts main session if unhealthy

**Root cause:** `parseBinding()` in `packages/harness/src/binding.ts` only reads YAML frontmatter — `title` and `acceptance` must be INSIDE the `---` block as YAML fields, not in the markdown body after it. The binding I wrote had title as a `# Heading` and acceptance as `## Acceptance Criteria` with `- [ ]` checkboxes in the markdown body — the parser saw both as empty.

**Fix:**
- Rewrote binding with `title:` and `acceptance:` list inside frontmatter YAML

- Cleared outcome.json and run.log.jsonl

- Spawned `build-975-retry` subagent (session: agent:main:subagent:f640bec0-7de0-4933-b831-ece4d9550d1f) to run harness directly on existing stack

**Lesson:** Binding format must have `title:` and `acceptance:` list in YAML frontmatter. The markdown body after `---` is supplementary context only — the parser ignores it for structured fields.
