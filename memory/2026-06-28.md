## Slack Ingest Workflow — Approved by Brad

Brad initiated a discussion in #engineering about the "ingest problem" — how to move from purely reactive (only building assigned issues) to proactive (ingesting work signals from Slack, Discord, meetings, Chase's todo list, Jira).

**Key decisions:**
- **Slack tagging = triage.** When someone tags me in a Slack thread, I read the context, create a well-scoped GitHub issue, self-assign, and build it.
- **Auto-assignment approved.** I self-assign issues I create from Slack tags. No need to wait for human assignment.
- **Priority labels.** `priority:high` / `priority:low` control build queue ordering. Unlabeled = normal priority.
- **Judgment gate stays.** I still refuse vague/unbuildable work — the tag gets it to me, my judgment decides if it's actionable.
- **Jira not needed right now.** GitHub Issues remains the backlog. Slack is the central nervous system.
- **No formal prioritization system yet.** Start simple, iterate.
