# FIDS Component Inventory

> Scope: P0 evidence inventory only. This document records implementations and live call sites inspected on branch `factory-os-p0-fids` at `f3b8217df`. It does not propose a Factory OS shell, a Production Order 360 experience, or a redesign of ERP or MES screens.

## Audit method and limits

- Evidence was taken from component implementations, their exports, and inspected ERP/MES call sites. Filenames alone were not treated as evidence.
- The branch does **not** contain `.codex/skills/factory-industrial-design/SKILL.md` or `docs/Factory_OS_UI_Gap_Analysis.md`; consequently their branch-local contents could not be audited. The missing governing inputs must be restored or committed before later P0 implementation work.
- “No direct test found” means the inspected test inventory did not identify a component-specific test. It is not a claim that the component cannot be exercised through an application test.
- Accessibility and responsive notes describe implementation evidence, not a completed assistive-technology or viewport test run.

## Inventory conclusions for P0

1. Reuse `@carbon/react` for controls, surfaces, overlays, tooltip behavior and semantic table markup; reuse the ERP table framework unchanged for industrial lists.
2. Wrap, rather than directly expose, the current color-based `Badge`/`Status` and source state-color registry. Current source adapters generally suppress unknown values, which violates the P0 unknown-state requirement.
3. Build the five P0 semantic components only. No inspected implementation provides generic object identity, decision-ready exception structure, evidence provenance/freshness, or an independent risk indicator.
4. Do not turn MES `ok`/`alert` wall-display states into the Factory OS machine ontology. They are a valuable source display model but have deliberately narrower meaning.
