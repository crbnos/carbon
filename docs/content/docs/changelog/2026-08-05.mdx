# August 5, 2026

This release introduces major improvements to assembly instructions versioning, stock movement corrections, the transfer wizard, and material picking behavior.

## Assembly Instructions Versioning

Assembly instructions now support full versioning with a self-referential `rootInstructionId` that groups version families together.

### New capabilities

- **Version switcher** — Navigate between version groups in the header
- **Make Active / New Version** — Publish or create new versions directly from the header
- **Automatic repointing** — Activating a version repoints all in-flight job operations on active jobs
- **Change-notice diffs** — Assembly instructions surface in change-notice diffs with resolved labels (no more raw UUIDs)

### Behavior changes

- Each version row carries a `rootInstructionId` grouping the version family
- The instructions table shows "Version N" plus a Versions hover card
- Activation is gated by a confirmation dialog (archives the prior version)
- In-flight work automatically builds from the newly published instruction

**Migration**: Existing assembly instructions receive `rootInstructionId = id`. No action required.

## Stock Movement Corrections

The count-level "Rectify" workflow (Posted → Draft → re-post) is removed. Posted inventory counts are now terminal. Corrections are made per-movement instead.

### New workflow

1. Open the movement in **Stock Movements**
2. Click **Correct Quantity**
3. Enter the quantity it should have been
4. Carbon books one **opposite movement for the difference**

### Key differences from rectify

- **Original count stays posted** — No reopening, no re-posting
- **Per-movement granularity** — Fix the specific row that's wrong, not the whole count
- **Linked corrections** — Each correction links back to its original
- **Effective quantity** — Re-correcting measures against the current net quantity (original + prior corrections), so corrections converge instead of stacking

### Accounting period handling

- The correction posts its journal into the **original movement's accounting period**
- **Locked periods** refuse corrections until unlocked
- **Closed periods** are permanent — corrections are blocked

**Migration**: The `rectify` route and its associated workflow are removed. Existing corrections (`correctionOfItemLedgerId`) continue to work unchanged.

## Transfer Wizard Redesign

The stock transfer wizard has been redesigned to reflect the **pull model**: you start from the bin that needs stock and pull it from somewhere.

### Changes

- **Transfer To** is now the master (step 1, destination)
- **Transfer From** is now the detail (step 2, source)
- Delta preview shows **stock arriving** at the destination
- Available flag surfaces when demand outruns available + incoming
- Lot picker offers **Scan** and **Select** tabs (no longer scan-only)
- Expired lots warn or block per the company's expiry policy

### Traceability improvements

- Storage Unit keys display as bin names, linking to quantities pre-filtered to that bin
- Stock Transfer resolves to the readable transfer id and links to the transfer document
- Direct transfers (two ledger rows) collapse into a single "from X to Y" activity entry

## Material Picking Behavior

Two new company settings control how material is picked and how short picks are handled.

### Auto-select material without picking list

**Location**: Settings → Production

When enabled, the MES issue-material screen auto-fills the FEFO lot suggestion for materials not on a picking list. The genealogy guard (single-parent check) still applies.

### Incomplete-pick policy

**Location**: Settings → Inventory

| Policy | Behavior |
| --- | --- |
| **Warn** (default) | Acknowledge modal when a short pick is detected |
| **Error** | Block completion until the shortage is resolved |

A new **Partial** status marks picking lists that completed with acknowledged short picks.

## MES Quantity Modal Fixes

The quantity modal (Complete/Scrap/Rework) now:

- **Accepts fractional quantities** — Up to two decimal places for items measured by weight, length, or volume
- **Guards against double-counting** — The quantity entered is validated against what's already complete, preventing sum errors
- **Caps at 2 decimals** — Prevents floating-point accumulation

## Job Traveler Materials

A new opt-in setting adds a materials (bill-of-materials) section to the job traveler PDF.

**Location**: Settings → Production → Job Traveler Materials

When enabled, the traveler includes:

- Item number
- Description
- Method type (Make, Purchase, Pull from Inventory)
- Quantity per the job's method

Off by default to keep travelers concise.

## Assembler Improvements

The Assembler's auto optimize policy now **measures first, predicts second**, delivering higher-fidelity models without manual tuning.

### What changed

- Pass 1 is lossless (weld + reorder + encode)
- If it fits the gates, the model ships untouched
- Failing passes predict the exact keep ratio needed
- Convergence re-anchors on what each pass achieved
- Fails immediately when the JSON structure alone exceeds the output cap

### Result

Real-world tests show STEP models 0.4–30 MB now shipping lossless under production gates. The previously guessed error budget no longer decimates models unnecessarily.

## Edge Functions Refactor

HTTP response construction is centralized into `lib/response.ts` for all edge functions.

### Changes

- Standardized JSON response helpers
- Consistent error handling and status codes
- Single source of truth for response structure

This refactor improves maintainability and reduces duplication across edge functions.
