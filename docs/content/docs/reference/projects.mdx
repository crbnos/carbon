A **project** holds a tree of <Term id="element">elements</Term>: the systems, requirements, tasks and tests that make up the work. Jobs, purchase order lines, purchase invoice lines, timesheets and material issues charge their cost to a project or to one of its elements. The <Term>project ledger</Term> records each charge, so you can compare it with the plan.

Open **Projects** in the sidebar. The module has **Projects**, **My Timesheet**, **Transfers**, **Labor Categories** and **Planning Groups**, plus **Approvals** when timesheet approval is on.

Click **New Project** on the project list. A new project starts in **"Draft"**.

Edit these fields later on the **Details** tab.

## Status lifecycle

The project status controls which charges the project accepts. The buttons in the project header move it.

| Status | Button that sets it | What the project accepts |
| --- | --- | --- |
| **"Draft"** | (new project) | Structure, plan lines and budget. No charges. |
| **"Released"** | **Release**, **Resume**, **Reopen** | New charges and postings. |
| **"On Hold"** | **Put on hold** | Postings against existing purchase order lines and jobs. No new charges. |
| **"Technically Complete"** | **Technically complete** | Late receipts, invoices and job completions, and reversals. No new charges. |
| **"Closed"** | **Close** | Nothing. The project is read-only. |

<Callout type="warn" title="Close is final.">
A Closed project cannot go back to any other status, and there is no project delete. Carbon refuses **Close** while the project has an open purchase order or an open job.
</Callout>

## Cost treatment

The <Term>cost treatment</Term> decides which account a project charge posts to. Carbon reads it when each charge posts.

| Treatment | Where the cost posts |
| --- | --- |
| **Statistical** | The charge keeps its own account, and the project is only a dimension on the journal line. Time posts no cost. An issue goes to **Indirect Materials & Services**. |
| **Expense** | The project's **Cost Account**, else the **Project Expense** account default. |
| **Contract** | The project's **Cost Account**, else the **Project WIP** account default. |
| **Capitalize** | The asset under construction that the charge builds. See [capital projects](#capital-projects). |

Set **Project WIP** and **Project Expense** at **Accounting → Default Accounts**. If an Expense or Contract project has no account, Carbon refuses its charges.

<Callout type="note" title="Statistical projects show no actual cost for time and issues.">
A Statistical project has no project account, so its time and issues write no project ledger rows. Its posted hours still count. Use Expense or Contract when you want the Costs tab to show actual cost.
</Callout>

### Capital projects

A Capitalize project builds fixed assets. When you release it, Carbon creates one asset under construction for the project and one for each element marked **Final asset** on its element page. Each charge posts to the asset of its nearest final-asset element, else to the project's asset. A job on a Capitalize charge number completes into that asset.

**Place in Service** in the project header, or on a final-asset element, moves the assets into an in-service class. The final-asset elements and everything below them move to a Completed state. A cost that posts after that adds to the in-service asset, and its depreciation spreads the addition over the asset's remaining life. See [fixed assets](/docs/reference/fixed-assets).

## Elements

An element is one node of the project tree. It has a type, a state, an owner, a priority, labels, dates, a milestone, an hours estimate and a budget.

- **Types:** `System`, `Requirement`, `Function`, `Task`, `Test Case`, `Folder` and `Parameter`. A Parameter's children must be Parameters.
- **Linked part:** any element except a Parameter can link an item and, for a serial-tracked item, one serial of it. The element page then shows the part's average hours and material cost on earlier elements linked to the same item, and **Issue material** offers the part's bill of materials first.
- **Readable id:** the project identifier and a sequence number, such as `ST-12`. The id stays the same when you move the element.
- **Chargeable:** on for a new element, except a Folder or a Parameter. A Parameter can never take charges.

Deleting an element also deletes every element below it. Carbon refuses the delete if that branch has costs, time, a job or a purchase order line.

### States

Each project has its own states, and each state belongs to a state group: **Backlog**, **Unstarted**, **Started**, **Completed** or **Cancelled**. A new project starts with Backlog, Todo, In Progress, In Review, Done and Cancelled. Manage states and labels on the project's **Settings** tab. The first charge to an Unstarted element moves it to the default Started state.

<Callout type="info" title="The state group decides whether an element takes charges.">
A new charge needs a Released project and an Unstarted or Started element. A posting against an existing commitment, such as a receipt or an invoice, also accepts a Completed element. Backlog and Cancelled elements accept nothing.
</Callout>

### Layouts and the element page

The **Elements** tab has six layouts:

- **List** shows the tree with a pill per property.
- **Board** has one column per state. Drag a card to change its state.
- **Table** adds hours and cost columns, and only it has **Group by**.
- **Tree** groups the children of each element in one box and draws the trace links between them. Drag from one element to another to add a link. **Focus** on a box shows only that part of the tree, and the breadcrumb goes back up. The type filter keeps the boxes, so the tree holds together. Click **N tests** or **N reqs** on a card to highlight its links.
- **Timeline** draws each element from its start date to its target date, with arrows for `precedes` links.
- **Reader** shows the project as a numbered document. **Export PDF** downloads it with the current filters.

Use **Display** to choose the properties you see. **Views** saves the layout, filters and display as a named view, for you or shared with everyone who can see the project. Without a view, the page opens the way you last left it.

Click an element to open it beside the list, or click **Open as a page**. The page has the sections **Children**, **Plan**, **Time & materials**, **Budget** and **Activity**. **Plan** holds three kinds of plan line:

- **Materials:** an item, a method (Pull from Inventory, Purchase to Order or Make to Order), a quantity, a unit cost and a required date. **Create Job** on a Make to Order line and **Create PO Line** on a Purchase to Order line make the job or purchase order line with the element's charge number.
- **Labor:** a <Term>labor category</Term>, hours and dates.
- **Other Costs:** a description and an amount.

### Milestones

A <Term>milestone</Term> is a dated window, such as a design review or a phase. Each element can belong to one milestone. The **Milestones** tab groups them as **Active**, **Upcoming** and **Completed**, with element progress, hours and cost on each row. **Burn chart** on a row plots the milestone's posted hours against an ideal line from its start date to its end date.

## Requirements, tests and parameters

A Requirement, a Test Case and a Parameter each have their own section on the element page.

- A **Parameter** is a value with a unit. Its source is **Manual**, **Sum of children**, **Smallest child**, **Largest child**, **Formula** or **Linked part**. A formula such as `= SNS-20 - SNS-21` uses readable ids, numbers, `+ - * /`, `min`, `max` and `abs`. **Linked part** reads the unit cost or a numeric custom field of the nearest linked part above it. A Parameter can carry an **Allocation** of its parent Parameter and a **Contingency**.
- A **Requirement** has a category, a target (`≤`, `≥`, `=` or a range) and the Parameter that measures it.
- A **Test Case** has a verdict and the quality procedure it runs.

A Requirement passes when its Parameter meets the target, with any contingency applied, and no Test Case that verifies it has failed. Units are free text and never convert.

## Trace links

A trace link connects two elements of one project: **satisfies**, **verifies**, **derives**, **implements**, **blocks**, **precedes**, **relates to** and **feeds**. Add them in the **Trace links** section of the element page or in the Tree layout. A formula writes its own **feeds** links.

When the name, description, target or Parameter value of an element changes, its incoming links turn suspect. Each shows a warning until someone clicks **Mark reviewed**.

## Templates and Build from part

Mark a project as a **Template** in the header's menu. **Copy project** opens a new project with **Copy from** set to it. A copy starts in **"Draft"** with no charges, time or assets.

**New → Build from part** on the Elements tab creates System elements under a parent element from one of three sources:

- **Serial:** what was consumed to build a serial, each element linked to its consumed serial.
- **Item:** the item's bill of materials. Bought components are left out unless you turn on **Include bought components**.
- **Template:** the elements of a template project.

Choose a depth from 1 to 5. The drawer previews the elements before it creates them.

## Baselines and change requests

The plan of a project is its elements, their names, types, budgets, estimates, part links, Requirement targets and Parameters, the trace links and the plan lines. State, owner, priority, labels, dates, milestone, verdict and comments are progress. Baselines, change requests and the plan lock cover the plan only. Progress stays editable at all times.

### Baselines

A baseline is a read-only copy of the plan. Click **Take Baseline** on the **Baselines** tab, or complete a milestone, which takes one named after it. Click a baseline to compare it with the current plan, or use **Compare with…** in its menu to compare two baselines. The compare lists each changed element in tree order, with its changed fields, plan lines and trace links.

### Change requests

A change request is a draft set of plan changes with a title and a reason. Click **New Change Request** on the **Change requests** tab. The Elements tab then opens with a banner, and every plan change goes into the change request. The live plan does not change. To open another change request, or to go back to the live plan, use the picker next to **Views** on the Elements tab. Rows the change request adds, changes or removes show **Added**, **Modified** or **Removed** in the List layout. Click **Leave** to go back to the live plan, and **Review** to open the change request.

The review page shows one card per changed element. Reviewers comment on a changed field or on the element, mark each element **Viewed**, and resolve comments. A **Viewed** mark clears when the element changes again in the change request.

1. **Submit** sends a Draft for review.
2. **Approve** applies the changes to the plan in one step and takes a baseline named "After" the change request. **Reject** sends it back with notes.
3. **Reopen** turns a Rejected change request back into a Draft.

If an [approval rule](/docs/reference/approvals) for project change requests exists, its approvers decide. Approval rules are available on the Business plan. Without a rule, anyone who can update projects approves.

<Callout type="warn" title="A change request applies whole, or not at all.">
If the live plan changed a row after the change request changed it, approval does not apply it. The page lists the conflicting rows. Click **Reopen**, check the rows, then submit again. A change request cannot delete an element that has costs, time, a job or a purchase order line.
</Callout>

A formula cannot change inside a change request. Leave the change request to edit it.

### Plan lock

Set **Lock Plan After Milestone** on the **Details** tab. When that milestone is completed, the Elements tab shows **Plan locked**, and a plan change outside a Draft change request is refused. **Open Change Request** goes to the change requests page.

## Charge numbers

A <Term>charge number</Term> is a project, or a project and one of its elements. The picker lists Released projects and their chargeable elements in an Unstarted or Started state. A **Charge Number** field is on:

- **Jobs.** You can change it while the job is Draft or Planned. After release it is fixed.
- **Purchase order lines.** On the item tab and on the G/L Account tab. An outside processing order has no picker, because its job decides the charge.
- **Purchase invoice lines.** A line converted from a purchase order copies the charge number of its PO line.
- **Reimbursement lines.** Each line takes a charge number. Charge lines show their charge number read-only.

**Settings → Projects → Require an element on every project charge** is off by default. Turn it on to make every charge name an element.

### Consume to project

A new job with a charge number has a **Consume to project** switch. When it is on, the job's material, labor and overhead post to the project account. When the job completes, nothing goes into stock, because the project consumes the output.

The switch turns on by itself for an Expense or Contract project. It is not available for a Statistical project, a job that does not complete to inventory, or a job for a sales order line.

## Time

Employees record hours against a charge number and a labor category. Each hour costs the category's rate on the entry date.

- **Log time** on the element page records hours on one date.
- **My Timesheet** shows a week, with one row per charge number and labor category. It is also in the user menu, and needs only an employee role. A **Timecard** row shows your clocked hours, in orange when they differ. Click **Submit week** to send the Draft hours.
- **My Timesheet** in the MES shows the same week for operators on the shop floor.

A <Term>timesheet</Term> entry moves through **"Draft"**, **"Submitted"**, **"Approved"** and **"Posted"**. A **"Rejected"** entry is editable again.

<Callout type="warn" title="You correct posted time. You do not edit it.">
A Posted entry is locked. Open its cell in the ERP timesheet and use **Correct** to give the new hours and a reason. Carbon reverses the posted hours and charges the new hours instead.
</Callout>

### Approvals

**Settings → Projects → Require approval of timesheets** is off by default, so submitted time posts at once. Turn it on to hold submitted time in **Approvals**. Approve or reject each entry, or use **Approve all** and **Reject all** for an employee's week. An approved entry posts at once, and a rejection needs a note. Approving needs the Projects update permission.

### Labor categories

A labor category is the cost class of an hour, such as Engineer II. Create them at **Projects → Labor Categories**, each with a history of **Cost Rate per Hour** and **Effective From** date. Expense and Contract time cannot post without a rate on its date. Set a person's default category on their **Job** tab in [People](/docs/reference/people).

## Issue material

**Issue material** on the element page takes stock from a storage unit and charges it to the element. **Return to stock** brings it back. **Inventory → Issue to Project** does the same with a charge number picker. The stock leaves at its carrying cost.

Log time and Issue material are not available on a Closed project or an element that does not take charges.

## Project stock

A project with **Project stock** owns the stock received for it. Other stock is **common stock**.

- A purchase order line charged to the project receives into its stock. So does a job with **Receive to project stock**.
- A job or an issue for the project draws the project's stock first, then common stock. Other demand draws common stock only. A sales shipment always ships common stock.
- Stock received into the project is inventory, not project cost. The project is charged when the stock is issued, or at receipt with **Charge at receipt**.

**Inventory → Quantities** filters by **Stock owner**. The item's storage units list each owner's stock on its own, and an inventory count gives each owner its own line, with a **Stock Owner** column. The project's **Stock** tab shows its stock by item, storage unit and lot, and the borrows it owes and has lent. A borrow past its due date shows in red.

### Planning

MRP plans a project with project stock on its own, as described in [planning](/docs/reference/planning#projects-with-project-stock). The project's plan-line materials are its demand. When common stock has more than it needs, MRP suggests a **Transfer** into the project; what is still short becomes an Order or Make for the project, charged to it. The project's manager owns these suggestions. An open borrow past its payback date shows an **Overdue borrows** badge on the project's header, linked to the Stock tab.

### Planning groups

<PlanBadge plan="Business" />

A **planning group** lets projects with project stock share supply of the same parts. MRP plans the members as one, so one order covers all of their demand. Each piece of that order is still assigned to a member, and it becomes the member's stock when it arrives.

Open **Projects → Planning Groups** and click **New**:

<FieldTable>
  <Field name="Name" type="text" required>Unique in the company.</Field>
  <Field name="Location" type="reference" required>Only projects at this location can join.</Field>
  <Field name="Priority Rule" type="enum" required>`Earliest Need` gives the group's supply to the earliest need date first. `Project Priority` gives it to the member with the lowest **Planning Priority** first.</Field>
  <Field name="Excess Rule" type="enum" required>Where received stock goes when no member needs it: `Common Stock` or `Exception Project`.</Field>
  <Field name="Exception Project" type="reference">The project that takes the excess. Required with `Exception Project`, and it must have project stock.</Field>
  <Field name="Active" type="boolean">The members of an inactive group are planned on their own.</Field>
</FieldTable>

A project joins on its **Details** tab after you save it: set **Planning Group** and **Planning Priority**. The project must have project stock and be at the group's location. You cannot delete a group while it has members, or purchase order lines or jobs made for it.

An order that MRP places for the group belongs to the group, not to one project. MRP **pegs** each part of it to a member's demand:

- A **Soft** peg sits on an order that has not arrived. MRP may move it on any run. A soft peg on a purchase order counts in the member's **Committed** cost.
- A **Hard** peg is made when the order is received, or when the job completes. The receipt or the job's output is split into one piece of stock per member, at its cost. MRP never moves a hard peg. What no member needs follows the excess rule.
- A **Manual** peg is a planner's choice, made with a reason. MRP keeps it. If its demand goes away, the peg shows an exception.

A price difference on the supplier's invoice is split over the members' pieces. On stock already used, each member's share is charged to its project as material variance. When one member is short and another has stock it does not need, MRP suggests a **Transfer**, or a **Borrow** with a payback date when the other member needs the stock back later.

A member project has a **Pegging** tab. It lists the group's orders that are for the project, with quantity, need date, state and element. Choose an **As of** date to see the pegs on that day. **Override** replaces a soft peg with a manual peg on another open order of the group.

### Transfers, borrows and paybacks

Another project's stock needs a transfer first. Open **Projects → Transfers**, or use **Transfer**, **Borrow** and **Payback** on the project's Stock tab. Add the lines while the transfer is Draft. A user who can update projects approves it, then posts it.

- **Transfer** moves stock between two owners at its cost. Either owner can be common stock.
- **Borrow** moves stock from one project to another until a payback due date. The stock moves at the lender's cost, and the borrower owes it back at that cost.
- **Payback** returns borrowed stock. The borrower's stock leaves at its current cost, and the lender gets it back at the cost it lent. When the returned stock cost more or less, the borrower takes the difference as **Payback Variance**, on its project and in the inventory adjustment variance account.

## Costs and the project ledger

The **Costs** tab rolls each element up with its children, and adds a **Project total** row:

- **Plan:** material, labor and other plan lines.
- **Budget:** the budgets set on the element and below it.
- **Committed:** the value of purchase order lines not yet received.
- **Actual:** the project ledger total.
- **Remaining:** budget less committed and actual.
- **Estimate:** the element's estimate at completion, else the larger of plan and committed plus actual.

A project that is a contract's project also lists the **Service orders** its contract covers, under the elements: one row per order with hours, actual, billed and unbilled amounts. Their actual cost adds to the **Project total**, and the total row says how much of it is service. You see these rows only with the permission to view service orders. See [Contract project](/docs/reference/service-orders#contract-project).

Click an element to see its ledger rows. The **Time & materials** tab lists unposted time, then the whole project ledger. The ledger only grows: a void or a correction adds a negative row.

<Callout type="note" title="Some actual cost needs accounting.">
Time, issues, receipts, charges and reimbursements write ledger rows in every company. Job material, job time and purchase invoices write ledger rows only when accounting is on.
</Callout>

## Indirect rates

<PlanBadge plan="Business" />

**Indirect rates** spread fringe, overhead and G&A cost over the projects that cause it, as a government contractor does. Carbon computes each pool's rate every month, puts **burden** on your projects, and bills it on Cost Plus contract lines.

### Pools

Open **Accounting → Indirect Pools** and click **New**:

<FieldTable>
  <Field name="Name" type="text" required>Unique in the company.</Field>
  <Field name="Pool Type" type="enum" required>`Fringe`, `Overhead`, `Material Handling`, `G&A` or `Service Center`.</Field>
  <Field name="Sequence" type="number" required>The order in which pools compute. A later pool takes the burden of an earlier one, so fringe on indirect labor goes into overhead.</Field>
  <Field name="Base" type="enum" required>What the rate applies to: `Total Labor Dollars`, `Direct Labor Dollars`, `Direct Labor Hours`, `Direct Material Dollars`, `Total Cost Input` or `Value Added`.</Field>
  <Field name="Applied Account" type="reference">The account that applied burden credits.</Field>
  <Field name="Applies to Projects" type="boolean">The burden run burdens project cost with this pool. Not for a Service Center pool.</Field>
  <Field name="Offset Absorbed Overhead" type="boolean">Overhead pools only. Subtracts the overhead your work centers already applied from each project's burden.</Field>
  <Field name="Active" type="boolean">An inactive pool computes no rate and burdens nothing.</Field>
</FieldTable>

Open a pool and click **Add** under **Accounts** to map a GL account to it. **Cost** is pool cost, the top of the rate. **Base** is part of what the rate applies to. A mapping can narrow the account to one dimension value, such as a department. One account is the cost of at most one pool. Project labor and material come into the base from the project ledger, by the project's cost objective, so a project account cannot be a Base account.

### Rates and the period run

Open **Accounting → Indirect Rates** and pick a fiscal year. The grid shows each pool's year-to-date rate by period, for the rate types `Provisional`, `Target`, `Actual` and `Final`.

- **Set Rate** enters a Provisional, Target or Final rate from a period to the end of the year.
- Locking an accounting period starts the **period run**. **Run Period** starts it by hand. The run computes the Actual rates, posts the burden catch-up to your projects, and bills burden on Cost Plus lines.
- **Run True-Up** appears when every pool that applies to projects has a Final rate for period 12. It burdens the year again at the Final rates and bills the difference.

Burden posts only into a Locked period. Each run posts the year-to-date burden less the burden already posted, so a rate change during the year is caught up on the next run. Unallowable cost stays out of a pool's rate and stays in its base.

**Burden Settings** picks the rate the run applies, `Provisional` or `Actual`. Burden rows are memo rows in the project ledger. **Post applied burden for Contract projects** also posts them to the general ledger: debit Project WIP, credit the pool's applied account.

**Statement** opens the Statement of Indirect Expenses for a period: each pool's accounts, the burden it carries from earlier pools, and its cost, base and rate. **ICE Export** downloads the incurred cost schedules A, B, C, E, G, H, I, K and L of the year, one CSV each.

### Burden on projects and contracts

The **Costs** tab of a burdened project lists **Burden by pool**, allowable and unallowable, under the element tree. Hover over an element's **Allowable** amount to see how much of it is burden.

A Cost Plus contract line bills burden at the Final rate when one exists, else at the Provisional rate, plus the line's fee. On the line's **Billing** tab, **Rate Ceilings** caps a pool's rate for that line. Burden bills by difference, so a rate change or the true-up adds a positive or negative item, and a posted invoice never changes.

## Budget control

<PlanBadge plan="Business" />

**Budget control** checks each charge against the budget of its nearest budgeted element: the element itself, else the closest element above it with a budget. Set it on the project's **Settings** tab, under **Project Control**:

<FieldTable>
  <Field name="Budget Control" type="enum" required>`None`, `Warn` or `Block`.</Field>
  <Field name="Tolerance" type="number">How far over the budget a charge may go before the check reports it. Empty reads as 0 %.</Field>
  <Field name="Material Measurement Point" type="enum" required>`Receipt` counts material when it is received. `Issue` counts it when project stock is issued (earned value only).</Field>
</FieldTable>

The check adds the new amount to the element's open purchase order lines and its direct actual cost. It runs when you save a purchase order line, finalize a purchase order, issue material to the project, and save a job that consumes to the project. **Warn** saves the document and shows the overrun. **Block** refuses it.

<Callout type="note" title="A timesheet is never refused.">
The work decides where time is charged, not the money left. On a timesheet, **Warn** and **Block** both save the time and show a warning. **Block** also sends the project owner a "Budget exceeded" notification.
</Callout>

## Earned value

<PlanBadge plan="Business" />

**Earned value** compares the work done with the plan and the cost. Set it up on the element page, under **Earned Value**:

- Turn on **Control account** on the element that a control account manager owns. Pick the **Control account manager**.
- On a chargeable element below a control account, pick a **Technique**. That element is a work package.

| Technique | Planned value (BCWS) | Earned value (BCWP) |
| --- | --- | --- |
| `0/100` | All at the end date | All when the element is completed |
| `50/50` | Half at the start date, half at the end date | Half when started, all when completed |
| `Percent Complete` | Spread over the dates | The budget times **Percent complete** |
| `Milestone` | Each child element's budget at its target date | The completed child elements |
| `Level of Effort` | Spread over the dates | Equal to the planned value |
| `Apportioned` | Spread over the dates | **Factor** times the **Base element**'s earned value |

The budget at completion (BAC) and the dates come from the latest [baseline](#baselines). Take a baseline before you read earned value. Actual cost (ACWP) is the direct cost in the project ledger below the work package.

The **Costs** tab shows one row per control account, with its work packages below it: BAC, BCWS, BCWP, ACWP, cost variance (CV), schedule variance (SV), the cost and schedule performance indexes (CPI, SPI), the estimate at completion (EAC) and the variance at completion (VAC). A CPI or SPI below 1 shows in red. EAC is ACWP plus the remaining budget divided by CPI.

Pick **Current** or a closed period in the period picker. **Current** is live. A closed period shows the snapshot that **Close Earned Value** took on the period close page while the period was locked. The snapshot never changes after the period closes. For a closed period, **Export ACWP** downloads its actual cost by charge number and element of cost, in hours and amounts, direct and burden, for an earned value tool such as Cobra.

## Stop-work orders

<PlanBadge plan="Business" />

A customer can order work on a contract to stop for 90 days (FAR 52.242-15). On a Released project with the cost objective `Direct`, open the **⋯** menu in the project header and click **Stop work**. Enter the order date.

The project goes **"On Hold"**: it takes no new charges, and open purchase orders and jobs still post. The header shows the order date, the end date 90 days later and the days left. Only **Resume** releases the project and clears the order. The status buttons stay hidden while the order is open.

## Troubleshooting

### "Project XX is Draft. Only a Released project takes new charges."
New time, issues and other new charges need a Released project. Release the project from its header. The same message names On Hold, Technically Complete or Closed for those statuses.

### "Element XX-12 of project XX is Backlog. Only an Unstarted or Started element takes new charges."
Move the element to an Unstarted or Started state. A Completed element still accepts postings against existing commitments (receipts, invoices, job completions, reversals), but no new charges.

### "Element XX-12 of project XX does not take charges."
The element's Chargeable property is off. Folder and Parameter elements start with it off. A Parameter can never be chargeable ("A Parameter cannot take charges").

### "Set Project Expense in Account Defaults before you charge an Expense project" / "Set Project Work in Progress in Account Defaults before you charge a Contract project"
The project has no Cost Account and the account default is empty. Set it at Accounting → Default Accounts. The UI label for Project Work in Progress is "Project WIP".

### "Set Indirect Cost in Account Defaults before you issue to a Statistical project"
An issue to a Statistical project posts to the Indirect Materials & Services account default. Set it at Accounting → Default Accounts.

### "The labor category of a timesheet entry has no cost rate on YYYY-MM-DD"
Expense and Contract time needs a cost rate effective on or before the entry date. Add one on the labor category (Projects → Labor Categories). Rates cannot be deleted; add a new one with a later Effective From date to change it.

### "This time is posted. Use a correction to change posted hours."
Posted timesheet entries are locked. Use Correct on the cell in the ERP My Timesheet. A correction writes a negative reversal and a replacement entry, both Submitted. An entry can be corrected once ("Only a posted entry needs a correction" for anything else).

### "The time is logged but did not post: ..."
Log time saved the entry as Submitted, but posting refused it with the reason shown. The entry stays Submitted and does not post.

### "The project has N open purchase order line(s). Receive or close them before you close the project."
Close refuses while any purchase order of the project is not Completed, Closed or Rejected, or any job is not Completed, Cancelled or Closed.

### "A Closed project cannot change"
Element create, update, move, delete and plan routes refuse a Closed project. Closed has no transition back.

### "This project has a stop-work order. Use Resume."
A project with an open [stop-work order](#stop-work-orders) stays On Hold. Click **Resume** in the project header.

### "Earned value is recorded for this element or an element below it. It cannot be deleted."
A closed period's earned value snapshot names the element as a work package or a control account. Keep the element.

### "The charge number is fixed once the job is released"
A job's charge number can change only while the job is Draft or Planned.

### "Project XX is Statistical. A job cannot consume to a Statistical project."
Consume to project needs an Expense or Contract project. It also cannot be combined with a fixed asset target or a sales order line.

### "Government-furnished stock of project XX can only move to a project of the same customer"
Approve and Post refuse a transfer, borrow or payback that moves a government-furnished project's stock to common stock or to a project of another customer. Pick a project of the same customer.

### "LOT-1 is in the stock of project XX. Transfer it first."
A job, an issue or a pick can draw only its own project's stock and common stock. Move the lot with a transfer or a borrow first.

### "Insufficient quantity in the stock of project XX to transfer"
Posting checks the from-owner's stock at each line's storage unit and lot. The line modal shows what is available there.

### Approvals is missing from the Projects menu
The Approvals item shows only when Settings → Projects → "Require approval of timesheets" is on. Approving needs the Projects update permission; an approver sees time on every project.

### The Costs tab shows no actual cost
Actual is the sum of the project ledger. A Statistical project writes no ledger rows for time or issues. Job material, job time and purchase invoice rows are written only when accounting is enabled. Committed is the unreceived value of PO lines on purchase orders in Planned, To Receive, To Receive and Invoice or To Invoice.

### "This capital project has no asset under construction. Release the project first."
A Capitalize charge needs the asset of its project or final-asset element. Release creates the assets; marking an element Final asset on a released project creates its asset.

### "Asset XX was capitalized; reverse the capitalization first"
A void of a document whose cost reached an asset under construction is refused once that asset is in service. A late cost (posted after Place in Service) can be voided until the asset is disposed.

### "A Parameter can only have Parameters as children"
A Parameter's children roll up into it, so only Parameters can go under a Parameter.

### "The serial belongs to a different item"
A linked serial must be a serial of the element's linked item. Picking another item clears the serial.

### "The plan is locked after XX. Open a change request to change it."
The project's lock milestone is completed. Open a change request on the Change requests tab and make the change there. Progress fields (state, owner, dates) are never locked.

### "XX-CR-1 is approved but cannot apply: the live plan changed under N of its rows."
A row the change request changes was changed in the live plan after the draft read it. Reopen the change request; Carbon lays its changes over the current plan. Check the rows and submit again.

### "A formula cannot change in a change request."
A formula writes its own feeds links, which a change request does not carry. Leave the change request (**Leave** on the banner) to edit the formula.

### Build from part leaves bill of materials lines out
The item source reads the method tree, which skips a line whose item has no cost record. The drawer shows the count. A Build from part parent cannot be a Parameter.
