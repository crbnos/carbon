# @carbon/dev

Developer CLI (`crbn` command) — worktree management, Docker Compose stacks, migrations, portless dev URLs, and app lifecycle.

## Always

- **Use the `crbn` CLI for stack operations** — `crbn up` boots Docker + apps, `crbn down` tears down, `crbn new` creates worktrees, `crbn status` shows state
- **Bash router handles `checkout`** — the `bin/crbn` shell script routes lightweight commands; heavy commands delegate to `tsx packages/dev/src/main.ts` (citty)
- **Respect the slot system** — `resolveSlot()` / `getSlot()` manage port allocation per worktree to avoid conflicts
- **Guard platform compatibility** — `bin/crbn` validates OS (POSIX only: Linux, macOS, WSL, Git Bash) and the Node floor, which it reads from the root `package.json` `engines.node`

## Ask First

- Changing Docker Compose service definitions or port mappings
- Modifying the portless proxy setup (`services/portless.ts`, `portless-setup.ts`)
- Adding new `crbn` subcommands (register in `src/main.ts` `subCommands`)

## Never

- Run `crbn up` without Docker running — it calls `ensureDockerRunning()` first
- Hardcode ports — use the slot/worktree resolution system
- Skip migrations on stack boot unless explicitly passing `--no-migrate`

## Validation Commands

```bash
pnpm --filter @carbon/dev test        # vitest
pnpm --filter @carbon/dev typecheck   # tsc --noEmit
pnpm --filter @carbon/dev smoke       # real containers: slots, fresh migrate, up, status, purge (~40 s, needs Docker; run from a worktree with no stack)
```

## Key Patterns

- **Commands**: `up`, `down` (`--purge` releases the slot), `new`, `init`, `remove`, `prune` (destroys stacks whose worktree directory is gone or that have no slot — the cleanup for worktrees deleted without `crbn remove`; `--all` destroys every stack on the machine and keeps worktrees and live slots; `--tree` also runs `git worktree prune`, and with `--all` removes this repo's linked worktrees — never the main checkout, the current one, or one with uncommitted changes or a detached HEAD; branches are kept), `list`, `status`, `reset`, `migrate`, `restore`, `copy` (env sync), `reload` (`crbn reload <service...>` → `docker compose up -d --force-recreate` a subset, applying compose/`.env.local` edits without restarting the app dev servers), `worktree-path <branch>` (prints the directory crbn gives a branch's worktree; `bin/crbn checkout` uses it, so the naming lives in TypeScript only). `reset` keeps the slot and touches only this worktree; orphans of other worktrees are `prune`'s
- **Restore** (`commands/restore.ts`): `crbn restore <file>` wraps `scripts/restore-database.sh` (the SQL is deliberately NOT ported) and adds worktree/`PORT_DB` resolution, a confirmation gate, and the trailing `databaseTasks` steps. The script truncates the local `supabase_migrations` ledger before restoring so the dump's own ledger lands — the ledger must travel WITH the schema, else the dump's older schema pairs with the local newer ledger and the trailing migrate step silently no-ops (leaving weeks of migrations missing while the ledger claims them applied). It deliberately does NOT boot a partial stack the way `crbn migrate` does — a restore rewrites `auth`/`storage`, whose schemas GoTrue and Storage build via their own migrations, so it requires a fully booted stack (`serviceSchemasReady` probes for GoTrue's `auth.users.email_confirmed_at`, `storage.objects`/`storage.buckets` AND Realtime's `realtime.messages` — the restore script's `to_regclass` guards mean a missing Storage schema would otherwise let the restore finish with no buckets seeded) and refuses otherwise — the backup carries the SOURCE schema, which is usually behind the branch. **`--scrub-emails` defaults ON here, inverting the script's opt-in default**, so a restore cannot drop real customer addresses into a local DB unless asked. By default the script truncates `storage.objects` (kept rows would point at files that live only in the source environment's backend, so downloads 404); pass `--keep-storage-objects` to retain them and the dump's buckets when you need realistic storage metadata, e.g. profiling storage RLS. The script fits the dump to this stack's own service schemas before psql reads it. It trims each non-public `COPY` to the local columns, drops a block whose table does not exist locally, and skips the backup's auth, storage and realtime admin-owned functions. A `COPY` that fails to parse makes psql read its rows as SQL, and that once swallowed the whole post-data section. Afterwards the script verifies every `public` index, constraint, trigger and policy against the dump by name, and the ledger row count. It re-adds a foreign key that cannot be validated (a backup is not one snapshot) as `NOT VALID`, and it exits 1 on any shortfall or missing storage buckets. So `crbn restore` never migrates a schema that did not land.
- **Stack boot** (`commands/up.ts`): Docker Compose → wait Postgres → wait service schemas → `databaseTasks` → spawn apps → portless aliases
- **Cloud boot** (`scripts/cloud-dev.sh`, `CARBON_DEV_CLOUD=1`, read only by `isCloudDev` in `stack-state.js`): `crbn up` starts `dockerd` when it is down, and starts the ERP/MES dev servers once the slot is configured, before the shared containers, the image pull, the worktree's containers and the migrations. Until the database is ready it keeps a `booting` marker holding its pid (like `asleep`, removed when that process is gone); the stack-activity middleware holds requests while it exists, then answers 503. The `carbon()` Vite plugin adds the cloud server config (warmup of the login page and app shell, any host). `cloud-dev.sh --prepare` caches dependencies and images, `--database` also a migrated database and Vite's cache.
- **Images are pinned by digest** (`name:tag@sha256:…` in `docker/*.yml`, and `SHARED_REDIS_IMAGE`): the digest is the multi-arch index's, the tag is for reading. A bump changes both (Dependabot's `docker-compose` updates do). Docker Hub allows 100 anonymous pulls an hour per IP; a cloud `dockerd` that crbn starts pulls through `mirror.gcr.io` (Google's cache of Docker Hub, which does not count against that limit and falls back to Docker Hub on a miss).
- **Image pulls retry** (`withExponentialBackoff`, `src/retry.ts`): `docker compose pull` and the missing crbn-shared images before its `compose up` get 4 attempts with jittered delays (2.5–5, 7.5–15, 22.5–45 s). That rides out a short throttle, not a used-up hourly window.
- **One database pipeline** (`databaseTasks` in `services/migrations.ts`): migrate → cron sync (shared mode) → config row → types (+ swagger in `up`) → authz sync. `up`, `migrate` and `restore` all run it; add a step there, not in a command. A shared-mode worktree's database and Storage tenant come from `provisionWorktreeData` (`services/shared-db.ts`: template, clone, tenant) and go with `dropWorktreeData`.
- **One `Stack` per worktree** (`stack.ts`): `currentStack()` / `stackAt(root)` resolve root, slug, compose project, recorded and effective mode, slot, ports, database target and container hosts once. Commands take it instead of re-deriving them; `dbUrl(db, role)` builds the connection string. `services/compose.ts` takes a `StackRef` (`root`, `slug`, `mode`) and never reads the mode file itself.
- **One teardown** (`teardown(stack, { volumes, purge, plain })` in `teardown.ts`): first SIGINT a `crbn up` running in another shell (`crbn up` keeps its pid in `<stateDir>/up`, `upFile` in `stack-state.js`) and wait for its own teardown, then stop the containers, or remove them by compose label with `volumes` or when the folder is gone, drop the `wt_` database (`volumes`, shared mode), stop the dev servers, release the portless aliases, flush the redis db (`volumes`), release the slot (`purge`; `removeSlot` deletes the whole `~/.carbon/stacks/<slug>`). Every step runs even when one before it failed; the failures are returned. `down`, `reset`, `remove` and `up` (Ctrl+C, `--run`) all call it.
- **Single sources**: `topology.ts` holds the compose names and ports (shared ports and containers, `crbn-shared`, `carbon-shared`, `REDIS_DB_MAX`, `PG_MAJOR`, isolated volumes, compose files, `projectName`, `stackHosts`), pinned against `docker/*.yml` by `topology.test.ts`. `paths.ts` holds every `~/.carbon` and `~/.portless` path. `constants.ts` holds the app registry (`APPS`: id, label, kind, URL env key, opt-in), the portless routes (`ROUTES`), `TLD`, `routeHost`, `OAUTH_HOST` and `LOCALHOST_PORTS`. `copy-files.ts` reads `package.json#crbn.copy`.
- **Migrations need three services, not just Postgres**: they write into `storage.buckets`, GoTrue's `auth` columns and `realtime.messages`, which Storage, GoTrue and Realtime build on first boot. `waitForServiceSchemas` gates every migrate on a fresh volume; standalone `crbn migrate` boots `postgres` + `gotrue` + `storage` + `realtime` for the same reason. A from-zero migrate takes about 5 s once they are up; what a kept volume saves a cold boot is the RLS sync and the seed (about 30 s), which only `cloud-dev.sh --prepare --database` uses.
- **Shared mode** (default; `.claude/rules/dev-shared-services.md`): a worktree runs 5 containers (`api-gw`, `gotrue`, `postgrest`, `realtime`, `inngest`). Postgres, PgBouncer, Storage, imgproxy, Inbucket, Redis and the edge runtime run once per machine in the compose project `crbn-shared` (`docker/docker-compose.shared.yml`); an isolated worktree starts only its `redis` and `edge-runtime` (`bootSharedForIsolated`, `.claude/rules/dev-shared-redis.md`, `.claude/rules/dev-shared-services.md`). Each worktree has its own database, `wt_<slug>`, cloned from `carbon_template`, and its own Storage tenant. Triggers in each database hand its pg_cron jobs and pg_net requests to `postgres` (`docker/worktree-forwarding.sql`). `crbn up --isolated` starts the private 9-container stack (`docker/docker-compose.isolated.yml` added to the dev file). The mode is in `~/.carbon/stacks/<slug>/mode`; a command that deletes data checks `recordedStackMode`, so a worktree an older `crbn` started keeps its volumes.
- **Stack size** (`StackSize` / `profileArgs` in `services/compose.ts`): `crbn up` starts the services the apps need (in isolated mode Inbucket included, for login emails). `--full` adds Studio, Postgres-Meta and a private edge runtime serving this checkout's functions, which the gateway uses instead of the shared one (compose profile `full`), and in isolated mode imgproxy; shared mode always runs imgproxy, Inbucket and the shared edge runtime in `crbn-shared`. The first three were ~40% of a stack's memory; imgproxy only converts HEIC and images the wasm pipeline refuses, and a transform attempted without it logs `imageTransformErrorMessage` (`@carbon/files`), which says to run `crbn reload imgproxy`. `--minimal` also drops Inbucket (profile `mail`). Picking **Studio** in the `crbn up` app picker (or `studio` in `CARBON_DEV_APPS`) enables profile `studio` instead, which holds only Studio and Postgres-Meta; it is a compose service, so a pick of Studio alone is still services-only mode. `crbn reload studio` starts Studio on a running stack. `generate:swagger` reads PostgREST through the gateway with the service role key (byte-identical to what Studio served), so it works at every size.
- **Hosted parity** (`docker/docker-compose.dev.yml`): service images track upstream self-hosting (`supabase/supabase` `docker/`); Postgres stays on the major the US production project runs. The gateway is Envoy (`api-gw`, alias `kong`) with upstream's config vendored in `docker/envoy` — local edits are marked `carbon:`, so an upstream sync stays a diff. Like the hosted gateway, it rejects a request without a valid `apikey` and serves bare `/rest/v1/` (the OpenAPI document) to the service role only. PostgREST caps reads at 1000 rows and searches `public,extensions`, matching `config.toml` `[api]`. The apps' Kysely pool connects through PgBouncer in transaction mode (`PORT_POOLER`, `SUPABASE_DB_POOLER_URL`; the shared `54329` in shared mode), as production's goes through Supavisor on 6543; scripts, migrations and database tests keep the direct `SUPABASE_DB_URL`. `API_EXTERNAL_URL` deliberately has no `/auth/v1` suffix (SAML URLs depend on it), so the gateway also routes GoTrue's un-prefixed `/verify` and `/sso/`.
- **Provision** (`commands/init.ts`): `crbn init` provisions an already-created worktree (canonical slug + env sync + skills) to match a `crbn checkout`; shared by `new`, the bash `checkout` post-create hook, and Conductor's `setup` (`.conductor/settings.toml`). It does NOT boot the stack — `crbn up` still mints ports/`.env.local`.
- **Worktree** (`worktree.ts`): `resolveSlug()`, `canonicalSlug()` (branch-derived `<repoBase>-<branch>`), the slot registry and the mode file. `getWorktreeRoot()` and `isValidBranchName()` are in `git.ts`; `ensureSlugAvailable()` is in `services/compose.ts`.
- **Services**: `compose.ts` (Docker), `migrations.ts` (Postgres/Supabase), `shared-db.ts` (worktree databases on the shared Postgres), `portless.ts` (`.dev` URLs; the interactive install/update/sudo setup is `portless-setup.ts`), `hibernate.ts` (idle supervision), `apps.ts` (dev servers)
- **Rolldown memory env** (`ROLLDOWN_MEMORY_ENV` in `services/apps.ts`): the react-router dev servers `crbn` spawns (not the assembler, whose planner uses rayon, and not an app's own `dev` script) get `MIMALLOC_ARENA_PURGE_MULT=0` and 4 rolldown/rayon threads, so dependency pre-bundling leaves ~320 MB in rolldown's native heap instead of ~1 GB (rolldown/rolldown#10985, #11233). Read when the binding loads, so set before Node starts; the shell or `.env` overrides them.
- **Aux spawners** (`services/apps.ts`): `spawnAssembler` (cargo; `crbn up` first refuses the assembler with an install hint while `assemblerMissingPrerequisite` names Rust, FCL or the OCCT build as missing, and builds into the shared `~/.cache/carbon-cargo-target`, `assemblerCargoTargetDir`) and `spawnEmailPreview` (`@carbon/documents` `email:previews` on `PORT_EMAIL` — the react-email server over `src/email/previews`, one fixture per email) — opt-in picker apps with their own spawners, not react-router dev servers
- **Vite helpers** (`vite.js`, exported as `@carbon/dev/vite`, typed by `vite.d.ts`): `carbon({ command, mode, locales, clientOnly, splitServer, precompress })` is each app's one plugin call, listed after `tailwindcss()` and `reactRouter()` (which stay in the app). It always adds stack activity, `dropStalledHmrClients` (terminates an HMR client whose unsent backlog is over 4 MB and not shrinking between two 5 s checks: a page the browser keeps connected but no longer runs, seen with headless Chrome's earlier pages, which otherwise holds every update in the server's memory; Vite's client reloads the page when it wakes) and Lingui's macro transform (with `linguiWithoutIdQuery`, which works around Lingui 6.9.0 parsing React Router's `?query`-suffixed route ids as plain JS), and on request react-aria's locale trimming (`locales`), `clientOnlyAlias` stubs (`clientOnly`), `splitServerByPackage` (`splitServer`: one server chunk per package, so Vercel's file trace stays fast; only modules loaded at startup are grouped) and `precompressedAssets` (`precompress`). Packages are imported only when their plugin runs; hooks use native filters. `applyDotenvToProcessEnv` stays a separate call. Lingui, `@lingui/conf` and the react-aria plugin are peer dependencies the apps provide
- **Vite is patched** (`patches/vite@8.3.3.patch`, every copy pnpm installs): `ensureWatchedFile` adds a file outside the root to the watcher once (on macOS each re-add cost one more FSEvents listener per transform, thousands per SSR reload; vitejs/vite#23940), and the SSR module runner maps stack traces with Vite's own `prepareStackTrace` instead of turning on Node's source-map support, which kept every module's map (~250–490 MB in the ERP). Frames inside externalized packages are no longer source-mapped. `src/vite-patch.test.ts` fails if either change is missing. A Vite upgrade fails `pnpm install` until the patch is redone or dropped.
- **App output goes through `lineWriter`** (`helpers.ts`), one per sink: when crbn's stdout is a pipe (Conductor, an agent, `| tee`) macOS writes it asynchronously, and a reader that fell behind queued every line in crbn's memory (207 MB in a test). Past `MAX_PENDING_OUTPUT` (4 MB) queued, lines are dropped and the count is printed once the pipe drains. It never waits on the sink, which would stall the dev servers. A terminal is written synchronously, so nothing queues there. Write any new app's output through it, not `sink.write`.
- **Spinners come from `ui.ts`, not `@clack/prompts`**: `tasks`, `spinner` and `progress` there print one line per step when stdout is not a terminal (an agent, a pipe, a log file) instead of every animation frame. Importing them from clack directly brings the frame noise back.
- **No command allow-list in `bin/crbn`**: the bash router runs from the main checkout while the TypeScript CLI runs from the current worktree, so the router passes anything it doesn't own (`checkout`, help, version) straight through. Register a subcommand in `src/main.ts` only.
- **Prompts need a terminal — say so**: a clack prompt with no TTY ends the process without a word. Every prompt calls `requireTerminal(what, instead)` (`prompts.ts`) first, which throws a one-line error naming the non-interactive route: `CARBON_DEV_YES=1` for the confirms (all through `confirmDestructive`), `crbn remove <branch-or-path...>`, `crbn new --yes <branch>`.
- **`--json`** on `status` and `list` prints machine-readable output (ports, redis db, containers, `mode`, `database`; `status` adds the `crbn-shared` containers, the shared connection count and the pg_net queue; never the JWT secret).
- **Read-only compose calls pass `--env-file`** (`envFileArgs`): compose interpolates the whole file before `ps`/`logs`, and it has values with no default, so without `.env.local` those calls fail and report an empty stack.
- **`restart: on-failure`** on every compose service: a crash restarts the container, a Docker daemon start does not. A stack only comes up through `crbn up`.
- **Heavy checks are queued machine-wide** (`bin/heavy-lock`): the `erp` typecheck, `generate:mcp` and `check:manifest` run through `packages/dev/bin/heavy-lock <command> [args...]`, so one runs at a time across every worktree. It takes an OS lock (`flock`, through Perl: Node has none and macOS ships no `flock(1)`) on `~/.carbon/heavy-check.flock`, then, like `flock(1)`, runs the command as a child and holds the lock until it exits, passing on INT/TERM/HUP sent to it. The command cannot hold the lock itself: TypeScript 7's `tsc` launcher replaces its process (`process.execve`), which drops every inherited fd. The OS frees the lock when `heavy-lock` exits, crash included, so there is no stale-lock cleanup. A `kill -9` of `heavy-lock` alone frees the lock while the command keeps running. A waiting run prints the holder's command and worktree. Without Perl or a writable home it runs the command unlocked. Never start one heavy command from inside another: it would wait on its own parent.
- **The slot registry is locked** (`lockRegistry` in `worktree.ts`): every change to `~/.carbon/dev-ports.json` is read → decide → write under a `mkdir` lock, written through a temp file + rename. Conductor boots workspaces concurrently; without the lock eight simultaneous `crbn up` left one slot in the file. Any new writer must take the lock.
- **Compose reads throw** (`composeRead` in `services/compose.ts`): `listContainers` and `listComposeServices` raise compose's own error instead of returning an empty list, which used to pass for "no stack".
- **Hibernation** (`services/hibernate.ts` + `stackActivity()` in `vite.js`), two stages while `crbn up` runs ERP/MES:
  - The files are a contract between `crbn up` and the Vite plugin: `stack-state.js` (plain JS, imported by both) names them, holds the wake timeout, and `isAsleepIn` removes an `asleep` marker whose `crbn up` is dead. The idle state machine is `superviseIdle` (`services/hibernate.ts`).
  - **Stack** — the dev servers touch `~/.carbon/stacks/<slug>/activity` on each request (`/api/inngest` excluded: Inngest polls it every 5 s). After `CRBN_IDLE_MINUTES` (default 30) without one, `crbn up` writes an `asleep` marker holding its pid and runs `docker compose stop`. The next request is held by the plugin while `crbn up` runs `bootStack` and waits for Postgres and the API — about 8 s.
  - **Dev servers** — they hold more than the containers (roughly 1 GB each). After `CRBN_APPS_IDLE_MINUTES` (default 120) `crbn up` aborts them (`spawnApps`' `signal`) and listens on their ports itself (`startWaker`). A request there cannot be handed over — the dev server needs that port — so a browser gets a page that polls and reloads, anything else a 503 with `x-crbn-waking`. Inngest polls and WebSocket upgrades (an open tab's Vite client probing for its server) do not wake it. That wake is about 40 s: the dev servers boot from cold.
  - Off for `--no-apps`, `--run`, `--borrow` (the owning `crbn up` does it) and `--no-hibernate`. Traffic that never reaches ERP/MES (`psql`, scripts on the API) does not count; `crbn migrate` and `crbn restore` wake a sleeping stack themselves (`wakeIfAsleep`). `crbn list` and `crbn status` show a hibernated stack.
- **Boot and deep wake show a "starting" page, not portless's 502** (`holdRoutes` in `services/hibernate.ts`): portless 0.16 has no hook for its 502 page, so before the dev servers spawn, `crbn up` points the `erp`/`mes` aliases at a page on a free port (the waking page's poll-and-reload, with `x-crbn-waking`), and points each back at its app (`setAlias`) once it answers any request — the first request, which is also Vite's first bundle. Gives up after 10 min and restores the alias anyway. The same hold covers a deep wake. Interactive `crbn up` with portless only, not `--run`.
- **Portless aliases are found by port** (`services/portless.ts`): `releaseAliases(ownPorts)` removes every route of each crbn prefix that points at one of a stack's ports, so a teardown needs no branch name and a worktree that switched branches loses its old aliases too. `crbn prune` also clears stale routes (`removeStaleAliases`): static aliases crbn registered whose port no live slot owns. `portless prune` only reaps routes that have a process. Every portless call goes through `runPortless`, which runs them one at a time: parallel writes raced the routes file.
- **Env**: `env.ts` — `renderEnv()` (`prefix: null` writes localhost URLs), `writeEnv()`, `writeStackEnv()` (write `.env.local` and load it), `loadEnvFiles()` (`.env.local` over `.env` into `process.env`). `CARBON_PORTLESS=0` turns portless off when `--portless` / `--no-portless` is not passed. URLs derived from the stack's ERP host (`ERP_URL`, `VERCEL_URL`, `INNGEST_SERVE_HOST`, `ONSHAPE_V2_OAUTH_REDIRECT_URL`) come from one `erpUrl`; a key a developer must keep fixed (a tunnel, a registered redirect URI) is pinned in `.env` with `#force`. Keys copied from `.env` (with an optional default) are listed once in `FROM_DOT_ENV`
- **`--run` flag**: scopes stack lifetime to a command (for headless/CI builds); `--volumes` also wipes the data (volumes or `wt_` database, and the redis db) on teardown
