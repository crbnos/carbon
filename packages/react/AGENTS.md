# @carbon/react

Shared UI component library — primitives, layout, data display, and overlays built on Radix, React Aria, and Tailwind.

## Always

- **Use existing components first.** Grep `packages/react/src/` before writing custom UI. Prefer built-in `variant` props over ad-hoc `bg-*`/`text-*` classes.
- **Use `cn()` for class merging** (`import { cn } from "@carbon/react"` — it's `twMerge(clsx(...))`). Never raw string concatenation for conditional classes.
- **Components live flat in `src/`** (e.g. `src/Button.tsx`), not under a `components/` subdirectory. Follow this convention for new components.
- **Concentric border radius**: outer radius = inner radius + padding. Card shell is `rounded-lg`; don't re-add borders/radius on CardContent.
- **Popover inside Drawer/Dialog**: `stopPropagation` on `onWheel`/`onTouchMove` of `PopoverContent` to prevent scroll-lock from swallowing events.
- **Closing animation (every modal and drawer)**: a dialog animates closed only when it stays mounted and its `open` prop goes false. `{disclosure.isOpen && <ConfirmDelete />}` removes it in the same render, so nothing animates — pass the condition as `isOpen`/`open`, and keep the record it shows until the next open (`useDrawerItem` in the ERP, `~/hooks`). State that must start fresh on each open goes in a body component inside `ModalContent` / `DrawerContent`, which Radix unmounts on close. When it cannot move there (a `ModalCard` form, or `Modal` / `ModalContent` props that read it), use `{d.openCount > 0 && <D key={d.openCount} open={d.isOpen} />}` — `useDisclosure().openCount` goes up each time the disclosure turns open (through `onOpen` or the `isOpen` prop). A route rendered as a dialog closes with `useRouteDialog()` (below), never by navigating directly. The positioning div in `DrawerPortal` runs a no-op exit animation matched to the panel's closing duration, and `ModalOverlay` runs for as long as `ModalContent` (200ms in, 150ms out, `ease-out`); Radix unmounts the portal as soon as that outer element stops animating, so change the durations together. Durations go on the state variants (`data-[state=open]:duration-300 data-[state=closed]:duration-200`): `animate-in`/`animate-out` set their own 150ms, which a bare `duration-*` cannot override. The motion scale (which element gets which duration and easing) is in `.claude/rules/conventions-ui.md`. Enforced by `no-unmounting-dialog` (`@carbon/checks`)

## Ask First

- Adding a new Radix/React Aria primitive dependency
- Changing the public API of `Button`, `Card`, `ModalDrawer`, or other widely-used components
- Modifying the barrel export in `src/index.tsx`

## Never

- Use `transition-all` when a scoped transition (`transition-transform`, `transition-colors`) works
- Create icon-only buttons without `aria-label` — use `IconButton` component instead
- Import from deep paths (`@carbon/react/src/Button`) — always use the package barrel or named sub-exports (`@carbon/react/Editor`, `@carbon/react/Chart`)

## Key Patterns

```typescript
import { Button, Card, HStack, VStack, IconButton, cn } from "@carbon/react";
```

- **Button** variants: `primary | secondary | solid | active | destructive | ghost | outline | link`; sizes: `sm | md | lg`; `shortcut` / `hideShortcutKey` / `shortcutGuard` bind a hotkey with a keycap badge (topmost-dialog guarded)
- **Shortcuts**: combos are named constants — shared `SHORTCUTS` in `src/shortcuts.ts`, never string literals at call sites. `useShortcutKeys` (one binding) and `useShortcutKeyMap` (entries array, dev-warns on duplicates) both delegate to react-hotkeys-hook — never add a hand-rolled keydown listener; `useShortcutSequence` (`g`-then-letter) is the lone exception (no library sequence support). `isEditableTarget` (the one editable-target check; `isTextEntryTarget` is its fields-only half, for menu keys); menu items take `shortcut={MENU_ITEM_SHORTCUTS.x}`, live only while their menu is open, `ShortcutHelpOverlay` (the `?` overlay; apps declare entries). Enter vs ⌘Enter and badge visibility are design decisions — see `.claude/rules/conventions-ui.md` § Keyboard shortcuts
- **Choice screens**: `ChoiceCardGroup` (card radios, `autoFocus` focuses the selected card) and `RadioGroupButton` (radio styled as a secondary Button) give one tab stop + arrow-key select; Enter stays free for the screen's continue action
- **Layout**: `VStack` / `HStack` with numeric `spacing` prop (maps to `space-y-*`/`space-x-*`)
- **Overlays**: `Drawer`, `Modal`, `ModalDrawer` (unified drawer/modal), `BottomSheet`, `Popover`. On phones `ModalContent` and `DrawerContent` render `DialogSheetContent` (`Modal.tsx`), a `BottomSheetContent`: the panel is the sheet's (the grabber that drags it down to close, its close button, its layer and backdrop) and the parts inside stay the modal's or drawer's own, which lay out for a phone. Every modal and drawer is therefore a bottom sheet there, with no change at the call site. Crossing the phone width while open (a large phone turned sideways) swaps the panel and remounts its content, as the phone sheets of `Popover`, `Select` and `DropdownMenu` do. `withCloseButton={false}` hides the sheet's close button (drag and a tap outside still close it); a dialog with no `onOpenChange` does not drag. A drag that would close the sheet first asks the content's `onPointerDownOutside` and `onInteractOutside`, as a tap outside does (`refusesDragDismiss`, `utils/dialog.ts`): a dialog that refuses an outside press (`preventDefault`, the document editor while it holds a draft, the CSV import) springs back instead, and closes only through its own buttons. A sheet fits its content up to 88dvh (a drawer too), `size="full"` on a drawer fills the screen, and a drawer's `position`, `overlay` and `container` do not apply on a phone. Their headers, titles and footers take the sheet's phone styles (`sheetHeaderClassName`, `sheetTitleClassName`, `sheetFooterClassName` in `BottomSheet.tsx`), so every sheet reads alike, and a sheet drags down from its grabber or any header carrying `data-bottom-sheet-header` (`BottomSheetHeader`, `ModalHeader`, `DrawerHeader`), unless the press is on a control in it (`startsSheetDrag`, `utils/dialog.ts`; a press in a sheet opened from this one is not this sheet's). The sheet takes the pointer only once it moves, so a tap on the header still reaches what is under it. Only a primary press drags, and only a sheet that can drag takes the header's touches (`touch-none` under `[data-sheet-draggable]`), so a header that cannot drag still pans. `Modal`, `Drawer` and `BottomSheet` share one root, `DialogRoot` (`DialogRoot.tsx`, re-exported from `Modal`). Toasts stay usable over an open dialog: an open modal, drawer or menu sets `pointer-events: none` on `<body>`, so `Toaster` sets `pointer-events: auto` on itself, and `ModalContent`, `DrawerContent`, `BottomSheetContent` and `ImageZoomViewer` wrap `onInteractOutside` in `keepOpenOnToast` (`utils/dialog.ts`), so a click on a toast does not close the dialog. A new Radix dialog content needs the same wrapper. `ModalContent` with `data-clear-backdrop` keeps its backdrop (an outside click still closes it) but drops the dim and blur, on a phone's sheet too, for a pane that previews the page's look (the account Appearance tab). A controlled `Modal`/`Drawer` with no `onOpenChange` cannot be dismissed and shows no close button; never pass a handler that does nothing (`no-noop-open-change` check). A route rendered as a modal or drawer takes `const dialog = useRouteDialog(to?)` and passes `open={dialog.open}` / `onClose={dialog.close}`: `close` sets `open` to false, and navigates once the dialog has gone (to `to`, else back when this tab has history, else the parent route, as `useCloseRoute` does). `RecordOutlet` provides the scope that connects them (`RouteDialogScope.tsx`): the content reports its exit from an effect cleanup when Radix unmounts it, and a `Submit` with unsaved changes reports through `useReportUnsavedChanges`, in which case `close` navigates at once so the blocker asks with the dialog still open. A combobox that reopens after its create modal waits with `afterDialogCloses` (`useDrawerItem().afterClose` in the ERP). The rules for dialogs are in `.claude/rules/conventions-ui.md` (Modals and Drawers)
- **Status**: a pill shows a tooltip only when given `tooltip` (extra detail) or `iconOnly` — never one repeating its label. `iconOnly` renders just the coloured icon, with the label in an always-on tooltip and as the `aria-label` of a `role="img"` badge (the children's text, `reactNodeToString`) — for dense rows and narrow drawers. `TooltipContent` takes `anchor` to position against a different element than the trigger, when one tooltip serves many small hover targets (a strip of bars)
- **App nav**: `NavRail` is the primary left nav of both the ERP and MES shells (56px icon rail, grows to 240px after a 150ms mouse hover or when pinned, left drawer below md that closes itself on navigation). The rail renders a pin toggle beside its `header` while expanded (it calls `SidebarProvider`'s `toggleSidebar`; ⌘B also pins, unless the provider gets `keyboardShortcut={false}`). Unpinning (the toggle, ⌘B or a page's `SidebarTrigger`) collapses the rail at once, also under the mouse; hover cannot reopen it until the pointer leaves the rail. The pin is not persisted: both apps pass `defaultOpen={false}`, and the provider writes no cookie (see `.ai/lessons.md`, "A cookie that was only ever written"). Optional `header` and `footer` slots; the header is a `NavRailSwitcher` — the company's logo (`logoLight`/`logoDark`, falling back to an initials `Avatar`) in the icon column with its name fading in, a menu trigger or, with `asChild`, a link, and a full-width row on phones; `NavRailGroup` adds a titled section that shows as a divider while collapsed. Entries are `NavRailItem` (a button, or `asChild` for a trigger/link) and `NavRailLink`; `label` is a string and doubles as the accessible name. A Radix menu/popover opened from a `NavRailItem` or `NavRailSwitcher` keeps the rail as it was (open or collapsed) until it closes. A mouse or touch click on an item dips its icon (`pulseNavIcon`, a 200ms WAAPI pulse; none for a keyboard click or under reduced motion); the ERP's module and record sidebars (`ContentSidebar`, `GroupedContentSidebar`, `DetailSidebar`) and the account modal's tabs (`@carbon/account`) call it from their rows' `onClick`, with `active:scale-100` so the row itself stays still, and `TabBarItem` (the phone tab bar) pulses its icon instead of scaling the tab. Render inside `SidebarProvider`; the shadcn-style `Sidebar*` primitives remain for other layouts
- **Theme colors**: a theme with `colors` (a gradient, solid or custom theme; `@carbon/utils` `theme-colors`) paints the shell. `useThemeValue` is the theme to render (a preview from `setThemePreview`, then a pending `theme` post, then the root loader: `resolveThemeValue`); `useSavedThemeValue` is the same without the preview (what a picker compares a pick with); `useThemePreview`'s setter replaces its last call, so `preview({})` ends it; `useThemeStyle` returns its `frame` / `rail` / `content` / `panel` styles, or `null` for a color theme; `useThemeContent(mode)` is the page tint for `<html>`, inside `/x` only. The ERP and MES shells compute `useThemeStyle()` once and pass it down with `ThemeStyleProvider`; `NavRail` and the ERP `CollapsibleSidebar` read it with `useShellThemeStyle()` (no router subscription of their own). The desktop `NavRail` applies `rail` and stays transparent over the shell's `frame`; the mobile drawer keeps the normal colors. `NavRailSwitcher` picks its logo by the frame's `tone` on larger screens and by the mode on phones, where no frame is painted
- **ColorPicker**: a hex color in a popover. The trigger reads "<label>: <value>", the label being `aria-label`, else `label`, else the enclosing `FormControl`'s label
- **Accessibility tree**: `RouteAnnouncer` (`@carbon/react/RouteAnnouncer`) and `DocumentHiddenMotion` (`@carbon/react/DocumentHidden`) are mounted once in each app's root. The first announces the new page title on navigation and moves focus to its `<h1>`, leaving focus alone while a drawer or modal opens; the second lets closing Radix menus, popovers and dialogs skip their exit animation in a hidden tab. A `Tooltip` keeps a hidden copy of its text so an icon-only trigger is named by it (and a named trigger described by it); its content therefore renders while closed, so keep effects and ids out of tooltip content. `toast.error` stays until dismissed. Inside a `FormControl`, `FormLabel` registers its text: `useInlineTriggerLabel` names an inline trigger after it ("Edit Customer"), and `LabelWithHelp`'s definition is the control's `aria-describedby`, not part of its name. Modals and drawers return focus to the last page control used (`utils/dialog.ts`)
- **Links that prefetch**: `PrefetchLink` is a React Router `Link` that prefetches its destination when the pointer goes down on it. Use it instead of `<Link prefetch="intent">`, which prefetches on a 100 ms hover and so runs a page's loaders for every row the mouse passes over. The click reuses the prefetch only because `prefetchCacheMiddleware` (`@carbon/utils`, in each app's root `middleware`) gives a prefetch response a few seconds of private cache; without it both requests reach the server and the click waits behind the prefetch. `NavRailLink` and both apps' `Hyperlink` already use it
- **Record outlet**: `RecordOutlet` is the `<Outlet>` of every route under `/x`. It remounts the page inside it when that page is shown for a different record (the params of the route in the outlet, not of a drawer below it), so nothing seeded from the previous record survives. A plain `<Outlet>` there fails the `no-bare-outlet` check
- **Data**: `Table` (TanStack), chart components via sub-exports (`@carbon/react/Chart`)
- **Week of hours**: `@carbon/react/WeekHours` — `WeekHoursChart` (a week as stacked bars per day on a 0–24 h scale: click below a day's bars to fill to there, drag a bar's lower edge, × to delete; it reports `onCommit` and the caller saves), `weekHoursTones`, and the pure layout (`snapHours`, `stackDay`, `fillToPointer`, tested). My Time in the ERP and the MES (`size="lg"`)
- **Drags**: `usePaneResize` sets a pane's height from a splitter by mouse, pen or finger, writing the height straight to the pane and committing on release (`touch-none` on the handle). `utils/drag.ts` has the pure release maths (`releaseVelocity`, `rubberBand`, tested). A `pointerup` reports the last move's position, so a release's speed always comes from the moves. A whole row or card that drags uses dnd-kit's `MouseSensor` and `TouchSensor` with a delay, not `PointerSensor`, so a swipe still scrolls, and `pointer-coarse:select-none`, or the hold selects its text; a small handle uses `PointerSensor` with `touch-none`
- **Rich text**: `@carbon/react/Editor` and `@carbon/react/RichText` (wraps `@carbon/tiptap`). Read-only rich text is `RichTextView`. `generateHTML` returns `""` on the server and hydration keeps a server `dangerouslySetInnerHTML` as it is, so `__html: generateHTML(…)` on a page's first load stays empty; `RichTextView` sets the HTML once the page has hydrated
- **Error boundary**: `@carbon/react/ErrorBoundary` — `RouteErrorBoundary` (exported as `ErrorBoundary` from a module layout so a failed loader shows inside the app shell; it shows the status code and, for a 4xx, the message the server threw — `routeErrorCopy` — so throw a `Response` whose body says what was wrong. A 5xx or thrown `Error` gets generic copy) and `RootErrorBoundary` (drop-in root `ErrorBoundary` for RR v7 that maps 404 / 503 (the maintenance screen) / other HTTP / thrown `Error` to a styled screen) plus its parts (`ErrorScreen`, `GlitchHeading`, `StatusReadout`, `MagneticLink`, `NoiseOverlay`). Both read a request that got no response (`isNetworkError`: a `TypeError` with one of the browsers' fetch-failure messages) as a lost connection, not a fault, and `useNetworkRetry` revalidates when the browser is back online or the tab is shown again, which clears the error. Wrap it in the app's `Document` and pass `env` so `window.env` is set (the client crashes hydration otherwise). Copy is intentionally hardcoded English, not i18n.
- **Avatar**: `src` may be a URL or a generated-avatar value from `user.avatarUrl` (`dicebear:<style>:<seed>[:<rrggbb>]`; the styles and value helpers are in `@carbon/utils` `avatar.ts`). A generated value renders as a plain `<img>` of `generatedAvatarUrl(value)` (`utils/generatedAvatarImage.ts`, which `Avatar` imports instead of the renderer so no bundle that shows an avatar carries DiceBear) — `/file/avatar/:value?v=<GENERATED_AVATAR_RENDER_VERSION>` — so it is in the server-rendered HTML and needs no client JavaScript. Every app (ERP, MES, academy) serves that path with a one-line route re-exporting `generatedAvatarLoader` from `@carbon/react/GeneratedAvatar`: it draws the SVG on the server with DiceBear 10 and answers `Cache-Control: public, max-age=31536000, immutable`, so a refresh reads it from the browser cache. **Bump `GENERATED_AVATAR_RENDER_VERSION` whenever the same value would draw differently** (a DiceBear upgrade, a change to the rendering options), or browsers keep the old image. The avatar picker draws in the browser instead (`GeneratedAvatarPreview`, `useGeneratedAvatar`), because a color drag makes a new value per step; there the DiceBear core and each style's JSON load with `import()` (`STYLE_LOADERS`, typed `Record<GeneratedAvatarStyle, …>`), never with a `with: { type: "json" }` attribute (Vite passes it to the browser, which rejects the JSON Vite serves as JavaScript, and the picker stays grey); the server side instead bundles `@dicebear/styles` through `ssrNoExternal` in each app's `vite.config.ts`, because Node refuses a package's JSON without the attribute. `generatedAvatarClassName(style)` picks the image classes: line-art styles on white (`bg-white`) in both themes, color styles on `bg-muted`. A value's optional background goes to DiceBear as `backgroundColor`; on a dark one (`isDarkBackground`, WCAG contrast) the styles that draw lines straight onto the background (`INK_OPTIONS`) get white ink. The app `Avatar` wrappers turn a stored value into `src` with `avatarSrc` (`@carbon/utils`); a new user has no avatar (initials) until they choose one
- **Announcement**: `AnnouncementBar` is the one-line bar both shells render above their page area for the deployment's announcement. It remembers a dismissal in localStorage per user and announcement id, and while shown sets `--announcement-height` on `<html>`; the ERP's `--content-inset` includes it, and a page sized from `100dvh` outside that variable must subtract it
- **Polish**: shadows over borders, `tabular-nums` for dynamic numbers, `active:scale-[0.98]` on pressables, `text-balance`/`text-pretty` for text wrapping
