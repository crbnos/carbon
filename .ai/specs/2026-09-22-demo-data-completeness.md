# Demo Data Completeness — every feature, every state

**Status:** Implemented (autonomous mode — user-delegated; uncommitted on the branch, awaiting the user's commit) · **Date:** 2026-09-22 · **Branch:** `feat/demo-data-completeness`
**Research:** `.ai/research/2026-09-22-demo-data-current-coverage.md`, `.ai/research/2026-09-22-app-feature-surface.md`, `.ai/research/2026-09-22-demo-data-validation-gate.md`

## Reading of the request (autonomous mode)

**What:** Expand the demo-data datasets (`packages/database/src/datasets/`) so a company seeded from any of the four industry templates exercises every major feature and reachable state of the ERP + MES apps — every list screen has rows, every detail screen opens, every status enum value a user can encounter appears somewhere. **Why:** demo data is the primary way prospects, staff and developers experience Carbon; today it covers ~40% of the app (no returns, no inspections, no maintenance, no picking, no posted documents, no payments, no HR, …). **Where:** the dataset engine (tiers), the dataset type, all four industry data packs, and the pre-commit validation. **Who:** anyone applying a demo template (Settings → Demo Data, onboarding, `pnpm db:seed:dev`). **Explicit user constraints:** leave out *files* (no document/file uploads); everything else in; be maximally thorough; no regressions; keep FK integrity; validation must block commits on invalid demo data with a clear message.

## Goals

1. Every user-reachable status enum value of every major document type appears in every dataset (matrix in Design §B).
2. Every module's list screens are non-empty and detail screens open: Sales (incl. RMA), Purchasing (incl. returns), Production (incl. batches, scrap/rework), Inventory (incl. picking, transfers, counts, tracked-entity states, supersession), Items (incl. taxonomy, revisions), Quality (incl. inspections, gauges, quality docs, risks, NCR depth), Resources (incl. maintenance, training, HR links), People (timecards, holidays), Invoicing (payments, memos, settlement states), Accounting (posted journals, periods, exchange rates, projects, FA lifecycle incl. disposal), Workflows (incl. run history), MES (queue, active work, picking, maintenance, batches, inspection).
3. Posted/partial document states exist with **hand-authored, internally consistent downstream effects** (item ledger, journals, settlements) — same pattern tier 3 already uses for opening stock.
4. All four industries stay in rough volume parity (the existing coverage contract), enforced structurally by required (non-optional) slice fields.
5. Validation: a commit with invalid demo data is blocked with a clear, actionable message — including when the local DB is down (new pure-TS layer).

## Non-goals

- **Files/uploads** (user-excluded): `document*`, storage objects, slide/file attachments. Notes and tags are data, not files — they are IN scope (light).
- Integrations config (`integration`, `companyIntegration`, `webhook`, `apiKey`, `oauth*`), SSO/passkeys/ITAR, notifications, agent threads, implementation hub, saved table views, `printJob`.
- Multi-company / intercompany / consolidation.
- EE-entitlement-authored data: approval rules, enforcement rules, demand/supply forecasts (`demandForecast*` are also wiped as transient; existing `demandProjection` seeding stays).
- Card transactions (Ramp-integration-coupled).
- New CAD models/thumbnails (existing bundled assets stay as-is).
- Derived/deprecated job statuses (`Overdue`, `Due Today`) — deliberate existing exclusion.
- CI enforcement (pre-commit remains the gate; CI was previously declined on cost).

Ledger-consistency invariant (new, load-bearing): **on-hand per (item, shelf) derived from all seeded `itemLedger` rows must remain ≥ 0 at every point and end equal to what pickable/genealogy flows assume.** The authoring convention: opening balances stay the baseline; posted receipts add; posted shipments/picks subtract only from items with sufficient opening stock. The pure validator (D) checks the end-state non-negativity per item/shelf from the dataset alone.

### C. Data integrity strategy

1. **Refs are loud.** Every cross-reference resolved via `need()`; the silent-skip/null-coalesce sites in tiers 01/03/04/06/09/12 (list in validation research) become throws. Genuine authored-optional fields keep `?? null` only where the column is nullable *and* the spec omitted the key on purpose (typed as optional).
2. **Posted docs carry their ledger.** Hand-authored `itemLedger`/`journal`/`invoiceSettlement` rows accompany every posted/paid state, balanced (`assertBalanced`-style check in the validator for journals; non-negative on-hand check for ledgers). GL account resolution stays class-based (extended to all 5 classes).
3. **Sequences respected.** All new readable-id documents go through the existing sequence machinery; insertion order rules (opportunities → statusOrders → releasedOrders) preserved and extended.
4. **Interceptors respected.** New inserts follow the adopt-don't-duplicate pattern (`jobMakeMethod`, `itemCost`) wherever a sync interceptor creates the row.
5. **Wipe compatibility.** All new tables are companyId-scoped → `wipeCompanyBusinessData` discovers them automatically; verify none belong in `PRESERVED_TABLES` (only `period` (global) and bootstrap-owned config do). Re-apply (second template onto same company) must stay clean — covered by acceptance test.
6. **Timezone/dates:** all offsets via `DayOffset` + `resolveDate`; `previousMonthEnd` for period ends; no JS `Date`.

### D. Validation (the commit gate)

1. **New `datasets/validate.ts` — pure, no DB.** Validates each dataset: every string ref resolves within the dataset (items, customers, suppliers, processes, work centers, shelves, warehouses, job keys, SO keys, price-break arity vs `rfqQuantityBreaks`); journal lines balance; end-state on-hand non-negative per item; `promisedDateOffset` within the 48-week horizon; `componentNodeIds` ⊆ bundled `graph.json`; every slice non-empty; supersession pairs reference distinct existing items. Runs (a) first inside `check-datasets.ts` — **before** the DB connection, so a broken dataset blocks the commit even with the DB down; (b) as a vitest suite (`datasets.test.ts`) so `pnpm test` covers it.
2. **`verify.ts` gains row-count floors.** After tiers, assert per-table minimum counts from a small manifest (e.g. `job ≥ 8`, `pickingList ≥ 2`, `nonConformance ≥ 3`…). Catches silent 0-row tiers. Still always rolls back.
3. **Hook semantics unchanged** (trigger path, skip env var, DB-down warning for the DB layer, clear block message). The pure layer never skips.
4. Baselines re-captured (`.ai/runs/`), structural sums extended (add itemLedger sum, journal balance), rule doc + datasets AGENTS.md updated.

## Design Decisions

| # | Decision | Choice | Rationale |
|---|---|---|---|
| 1 | Posted/partial documents | Hand-authored downstream rows in-transaction | Edge functions can't run inside the seed transaction (architectural); tier 3 already sets the precedent; the alternative (post-commit edge calls) breaks all-or-nothing apply and verify rollback |
| 2 | New capability placement | Extend existing slices + one new `ops` slice for tier 10 | Tier 10 was reserved for exactly this (its own comment); keeps tier ordering contract intact |
| 3 | Industry parity | All four datasets get full new data | Volume is the coverage contract; onboarding shows all four; required (non-optional) type fields enforce parity at compile time |
| 4 | Silent skips | Become `need()` throws | A demo dataset is first-party data; a typo should fail the gate, not degrade. Data fixed in same change, so no behavior break |
| 5 | Pure validator placement | `check-datasets.ts` pre-DB + vitest | Closes the "DB down → warn+pass" hole without changing the deliberate DB-layer skip |
| 6 | EE-gated features (approvals, enforcement, forecasts) | Excluded | Seeding data behind an entitlement gate is invisible in community/self-hosted demos; forecasts additionally wiped as transient |
| 7 | Files/documents module | Excluded | Explicit user instruction |
| 8 | Card transactions, intercompany | Excluded | Integration-coupled / multi-company out of scope |
| 9 | Quote-line methods (`quoteMakeMethod` fill) | Attempt; fall back to documented ceiling if job-helper reuse isn't clean | Quote costing screens are a major demo surface, but the helper was built for jobs; plan verifies feasibility first |
| 10 | Workflow run history | Seed terminal runs directly | Rows are read-only history for the UI; engine never re-reads terminal runs |
| 11 | Open MES production event | One open Setup event for the applying user | Makes MES “Active”/timecard live; bounded risk (one row, user can end it) |
| 12 | CI check | Not added | Previously declined on cost; pre-commit + vitest suffice |

## Autonomous Decisions (high-stakes first)

1. **Seeding posted documents with hand-authored ledger/settlement effects** (Decision 1) — bypasses the posting engines; mitigated by balance/non-negativity validation and per-table acceptance checks. *(Rung: codebase precedent — tier 3/tier 6 already write ledger + genealogy rows directly.)*
2. **Scope exclusions** (Decisions 6–8, non-goals list) — narrows "every feature" to features that are demoable in a community, single-company, no-files context. *(Rung: product judgement + user's own "leave out files".)*
3. **Making silent skips throw** (Decision 4) — a behavior change in the shared seed path; safe only because all four data packs are fixed in the same change. *(Rung: user's stated intent — validation must catch invalid data.)*
4. **New required slice/fields → compile-breaking Dataset shape** (Decision 3) — any out-of-tree dataset would break; none exist. *(Rung: codebase precedent — DatasetKey is already a closed union.)*
5. **Pure validator wired before the DB layer in the pre-commit path** (Decision 5) — commits can now be blocked with no DB running, which is precisely the user's requirement. *(Rung: user's stated intent.)*
6. Branch/workflow: work directly on `feat/demo-data-completeness` in this checkout; **no commits without explicit user permission** (standing user rule overrides ship-it's commit steps).
7. Smaller calls: open MES event (D11), workflow run history (D10), quote-methods attempt (D9), notes/tags in scope but light, crews/equipment pending plan-time table verification.
8. **Cluster C4 (Task 6) resolutions:**
   - The no-quote reason column is `salesRfq.noQuoteReasonId` (not quote/quoteLine — `updateSalesRFQStatus` writes it), so it is wired as `SalesRfqSpec.noQuoteReason` on the Closed RFQ that pairs with each dataset's Lost quote; tier 01 now registers `nqr:<name>` refs.
   - `SalesInvoiceSpec.key` is OPTIONAL (`sinv:<key>` in ctx.refs.misc) so the pre-existing Draft invoices stay byte-identical; all six new lifecycle invoices carry keys (C9 settles "paid"/"partial").
   - `SalesReturnSpec.salesOrder` sits at the HEADER (schema: `salesReturnOrder.salesOrderId`; the line-level column is `salesOrderLineId`, which the seed leaves null). `returnReason` is a header field applied to every line's `returnReasonId` (per-line in schema).
