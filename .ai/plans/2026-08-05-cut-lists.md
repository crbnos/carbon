# Cut Lists — implementation plan

**Spec:** .ai/specs/2026-08-04-cut-lists.md (all decisions resolved, D1–D6)
**Research:** .ai/research/2026-08-04-cut-lists.md
**Branch:** feat/cut-lists

Scope: all three phases. Phase 1 is fully specified. Phases 2–3 are specified at
task grain with explicit scouting anchors; **re-run /plan for Phase 2 detail
after Phase 1 ships** (schema truth will have moved) — that checkpoint is Task 14.

Conventions that bind every task (from `.claude/rules/` + `.ai/lessons.md`):

- Permissions: cut list tables use `production_<action>`; `itemStockDimension`
  mirrors whatever scope the `material` table's policies use (verify, don't
  assume). Never invent a new permission family.
- Migrations: `pnpm db:migrate:new <name>` (never hand-pick timestamps, never
  `000000` HHMMSS), bare `NUMERIC` (no precision), no `itemReadableId` columns,
  four RLS policies named `SELECT`/`INSERT`/`UPDATE`/`DELETE`, views
  `WITH(SECURITY_INVOKER=true)`.
- After any migration: `pnpm db:migrate` (applies + regenerates types). Never
  `db:build` (doesn't exist). Never rebuild the DB.
- Services: client first arg, return raw `{ data, error }`, scope every query by
  `companyId`, `sanitize()` update payloads.
- Forms: `validator(schema).validate(formData)` from `@carbon/form`, never
  `schema.parse()`.
- Typecheck is always scoped: `pnpm exec turbo run typecheck --filter=erp` (or
  `--filter=mes`). Never whole-repo.
- PostgREST embeds on composite-FK relationships: embed by target table name
  (`supplier(id, name)`), never `alias:fkColumn(...)` (PGRST200).

```sql
-- Status enum
CREATE TYPE "cutListStatus" AS ENUM ('Draft', 'Released', 'In Progress', 'Completed', 'Cancelled');

-- 1:1 stock dimensions for material size-items (spec D1)
CREATE TABLE "itemStockDimension" (
    "itemId" TEXT NOT NULL,
    "companyId" TEXT NOT NULL,
    "stockLength" NUMERIC,
    "stockWidth" NUMERIC,
    "stockThickness" NUMERIC,
    "unitOfDimension" TEXT NOT NULL DEFAULT 'in' CHECK ("unitOfDimension" IN ('in', 'ft', 'mm', 'cm', 'm')),

    "createdAt" TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT NOW(),
    "updatedBy" TEXT REFERENCES "user"("id"),
    "updatedAt" TIMESTAMP WITH TIME ZONE,
    PRIMARY KEY ("itemId", "companyId"),
    FOREIGN KEY ("itemId", "companyId") REFERENCES "item"("id", "companyId") ON DELETE CASCADE,
    FOREIGN KEY ("companyId") REFERENCES "company"("id") ON DELETE CASCADE
);
CREATE INDEX "itemStockDimension_companyId_idx" ON "itemStockDimension" ("companyId");
CREATE INDEX "itemStockDimension_createdBy_idx" ON "itemStockDimension" ("createdBy");

-- The document (spec: cutList)

    "companyId" TEXT NOT NULL,
    "cutListId" TEXT NOT NULL,
    "locationId" TEXT,
    "processId" TEXT,
    "workCenterId" TEXT,

    "kerf" NUMERIC NOT NULL DEFAULT 0,
    "endTrim" NUMERIC NOT NULL DEFAULT 0,
    "gripMargin" NUMERIC NOT NULL DEFAULT 0,
    "minRemnantLength" NUMERIC NOT NULL DEFAULT 0,

    "assignee" TEXT REFERENCES "user"("id"),

    "completedDate" TIMESTAMP WITH TIME ZONE,
    "customFields" JSONB,
    "tags" TEXT[],
    "createdBy" TEXT NOT NULL REFERENCES "user"("id"),
    "createdAt" TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT NOW(),
    "updatedBy" TEXT REFERENCES "user"("id"),
    "updatedAt" TIMESTAMP WITH TIME ZONE,
    PRIMARY KEY ("id", "companyId"),
    FOREIGN KEY ("companyId") REFERENCES "company"("id") ON DELETE CASCADE,
    FOREIGN KEY ("locationId", "companyId") REFERENCES "location"("id", "companyId"),
    FOREIGN KEY ("processId", "companyId") REFERENCES "process"("id", "companyId"),
    FOREIGN KEY ("workCenterId", "companyId") REFERENCES "workCenter"("id", "companyId")
);
CREATE INDEX "cutList_companyId_idx" ON "cutList" ("companyId");
CREATE INDEX "cutList_createdBy_idx" ON "cutList" ("createdBy");
CREATE INDEX "cutList_processId_idx" ON "cutList" ("processId");
CREATE INDEX "cutList_locationId_idx" ON "cutList" ("locationId");
ALTER TABLE "cutList" ADD CONSTRAINT "cutList_companyId_cutListId_key"
    UNIQUE ("companyId", "cutListId");

-- Demand lines (spec: cutListLine)
CREATE TABLE "cutListLine" (
    "id" TEXT NOT NULL DEFAULT id(),
    "companyId" TEXT NOT NULL,
    "cutListId" TEXT NOT NULL,
    "jobId" TEXT,
    "jobMaterialId" TEXT,
    "itemId" TEXT NOT NULL,
    "pieceLength" NUMERIC NOT NULL,
    "pieceWidth" NUMERIC,
    "quantity" INTEGER NOT NULL,
    "quantityCut" INTEGER NOT NULL DEFAULT 0,
    "order" DOUBLE PRECISION NOT NULL DEFAULT 1,
    "createdBy" TEXT NOT NULL REFERENCES "user"("id"),
    "createdAt" TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT NOW(),
    "updatedBy" TEXT REFERENCES "user"("id"),
    "updatedAt" TIMESTAMP WITH TIME ZONE,
    PRIMARY KEY ("id", "companyId"),
    FOREIGN KEY ("companyId") REFERENCES "company"("id") ON DELETE CASCADE,
    FOREIGN KEY ("cutListId", "companyId") REFERENCES "cutList"("id", "companyId") ON DELETE CASCADE,
    FOREIGN KEY ("jobId", "companyId") REFERENCES "job"("id", "companyId") ON DELETE SET NULL,
    FOREIGN KEY ("itemId", "companyId") REFERENCES "item"("id", "companyId")
);
CREATE INDEX "cutListLine_companyId_idx" ON "cutListLine" ("companyId");
CREATE INDEX "cutListLine_cutListId_idx" ON "cutListLine" ("cutListId");
CREATE INDEX "cutListLine_jobId_idx" ON "cutListLine" ("jobId");
CREATE INDEX "cutListLine_itemId_idx" ON "cutListLine" ("itemId");
CREATE INDEX "cutListLine_createdBy_idx" ON "cutListLine" ("createdBy");

-- Cutting process flag + machine defaults (spec D3)
ALTER TABLE "process"
    ADD COLUMN IF NOT EXISTS "isCuttingProcess" BOOLEAN NOT NULL DEFAULT FALSE,
    ADD COLUMN IF NOT EXISTS "defaultKerf" NUMERIC,
    ADD COLUMN IF NOT EXISTS "defaultEndTrim" NUMERIC,
    ADD COLUMN IF NOT EXISTS "defaultGripMargin" NUMERIC,
    ADD COLUMN IF NOT EXISTS "defaultMinRemnantLength" NUMERIC;

-- Dimensionality on material forms (drives 1D vs 2D fields)
ALTER TABLE "materialForm"
    ADD COLUMN IF NOT EXISTS "dimensionality" TEXT CHECK ("dimensionality" IN ('1D', '2D'));
UPDATE "materialForm" SET "dimensionality" = '1D'
    WHERE "code" IN ('roundbar','roundtube','recttube','squaretube','flatbar','hexbar','angle','channel','wbeam')
    AND "companyId" IS NULL;
UPDATE "materialForm" SET "dimensionality" = '2D'
    WHERE "code" IN ('sheet','plate','treadplate')
    AND "companyId" IS NULL;

-- Cut requirements on BOM lines (spec FR-2)
ALTER TABLE "methodMaterial"
    ADD COLUMN IF NOT EXISTS "cutLength" NUMERIC,
    ADD COLUMN IF NOT EXISTS "cutWidth" NUMERIC,
    ADD COLUMN IF NOT EXISTS "grainLocked" BOOLEAN NOT NULL DEFAULT FALSE;
ALTER TABLE "quoteMaterial"
    ADD COLUMN IF NOT EXISTS "cutLength" NUMERIC,
    ADD COLUMN IF NOT EXISTS "cutWidth" NUMERIC,
    ADD COLUMN IF NOT EXISTS "grainLocked" BOOLEAN NOT NULL DEFAULT FALSE;
ALTER TABLE "jobMaterial"
    ADD COLUMN IF NOT EXISTS "cutLength" NUMERIC,
    ADD COLUMN IF NOT EXISTS "cutWidth" NUMERIC,
    ADD COLUMN IF NOT EXISTS "grainLocked" BOOLEAN NOT NULL DEFAULT FALSE;

-- Ledger document type for confirmation postings
ALTER TYPE "itemLedgerDocumentType" ADD VALUE IF NOT EXISTS 'Cut List Consumption';
```

   ```
     consumed: [{ trackedEntityId, quantityConsumed }],   // batch-tracked path
     untrackedConsumed: [{ itemId, quantity, storageUnitId? }], // untracked path
     remnants: [{ fromTrackedEntityId, length, storageUnitId? }],
     scrap: [{ fromTrackedEntityId?, itemId?, quantity, scrapReasonId? }] }
   ```
2. Pure helper `buildCutListPostingPlan(...)` takes the payload + fetched rows
   and returns the ledger rows, entity updates, and split instructions —
   unit-tested without a DB. Rules:
   - Consumption ledger rows use `entryType: "Consumption"`,
     `documentType: "Cut List Consumption"`, `documentId: cutListId`. One row
     per served job (split `quantityConsumed` across the lines' jobs
     proportionally to `pieceLength × quantityCut`; lines with no job book to
     the cut list itself). Phase 1 allocation IS this proportional split
     (spec D5) — Task 20 only adds time/variance, not a different rule.
   - Remnant creation reuses the existing split flow: child `trackedEntity`
     via the same mechanism as `trackedEntitiesToOperation`'s partial
     consumption, then stamp `attributes` with
     `{ "Remnant": true, "Length": <length>, "Unit": <unitOfDimension> }` and
     copy the parent's `Heat Number` attribute if present. Bin resolution MUST
     use `resolveTrackedEntityBin` (lesson: never `.find(...).storageUnitId`).
   - Remnants shorter than the cut list's `minRemnantLength` are rejected by
     the validator (client sends them as scrap instead).
   - Update `cutListLine.quantityCut`, then set the cut list `status` to
     `Completed` + `completedDate` when every line's `quantityCut ≥ quantity`
     (partial confirmations leave it `In Progress`).
   - Stamp `updatedBy` on every UPDATE and never write a nullable user id into
     a NOT NULL audit column (lesson: COALESCE to `createdBy`).
3. Wire the case into the handler using a Kysely transaction like the sibling
   cases. If the split machinery in `trackedEntitiesToOperation` is not
   extractable without large refactors, STOP and report — do not fork-copy 200
   lines of split logic; propose the minimal extraction first.
